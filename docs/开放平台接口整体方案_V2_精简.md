# 开放平台接口整体方案（V2 精简对外版）

> 文档生成日期：2026-08-03
> 目标：对外开放能力收敛，避免暴露过细原子能力
> 适用对象：业务系统、外部集成方、数字员工平台

## 1. 设计原则

1. 对外只开放业务级能力，不直接暴露内部细粒度流水线接口。
2. 统一使用稳定的北向 API 路径，内部能力通过平台编排实现。
3. 权限不降级：知识库、文档、检索结果均按调用方权限过滤。
4. 对外返回统一结构，降低接入方改造成本。

## 2. 对外能力边界（仅四类）

| 能力域 | 对外目标 | 不对外暴露的内部细节 |
| --- | --- | --- |
| 知识库管理 | 创建库、修改库信息 | 团队审批、内部工作流节点、底层模型参数 |
| 知识管理 | 上传知识到库、文档解析 | 切片回调、内部缓存页级接口、内部任务编排细节 |
| 知识索引 | 索引构建/重建、索引任务状态查询 | Solr/向量库底层写入细节、分段原子控制 |
| 知识检索 | 统一检索问答 | 多检索器细分路由、重排器内部参数 |

知识库类型约束：
1. `personal`（个人库）：仅库创建者可见，默认最小共享范围。
2. `team`（团队库）：团队成员可见，需校验团队成员关系与团队权限。
3. `enterprise`（企业库）：企业范围可见，需结合租户与组织权限策略。

知识库参数约定：
1. `kbName`：知识库展示名称，建议在同组织范围内保持唯一，便于前端列表与权限管理。
2. `kbType`：知识库类型，取值为 `personal`、`team`、`enterprise`，决定后续 `teamId`/`orgId` 的必填规则。
3. `teamId`：团队知识库标识，`kbType=team` 时必填，用于团队归属与成员权限校验。
4. `orgId`：企业知识库组织标识，`kbType=enterprise` 时建议填写，用于租户隔离与组织授权。
5. `kbDesc`：知识库描述，建议写明业务场景、责任人和适用边界。
6. `bizDomain`：业务域标签，例如 `hr`、`finance`、`customer_service`，用于分类与治理统计。
7. `visibility`：可见范围，`private` 表示私有可见，`org` 表示组织内可见。
8. `metadataSchema`：元数据字段定义数组，用于约束知识库数据录入、检索过滤和权限标签；元素对象建议包含 `name`、`type`、`required`、`description`、`defaultValue`、`enum`、`pattern`、`minLength`、`maxLength`、`example`。

知识库类型与操作边界：

| 知识库类型 | 必填标识 | 默认可见范围 | 创建/修改权限 | 上传/解析权限 | 索引权限 | 检索权限 |
| --- | --- | --- | --- | --- | --- | --- |
| personal | 无 | 创建者本人 | 创建者 | 创建者 | 创建者 | 创建者 |
| team | teamId | 团队成员 | 团队管理员/Owner | 团队编辑及以上 | 团队管理员/Owner | 团队成员（按角色） |
| enterprise | orgId（建议） | 企业授权范围 | 企业知识管理员 | 企业授权编辑角色 | 企业知识管理员 | 企业授权用户 |

统一约束：
1. `kbType=team` 时，必须校验 `teamId` 与调用主体的成员关系。
2. `kbType=enterprise` 时，必须校验调用主体的企业范围授权。
3. `ingest/parse/reindex/search` 必须在知识库可见范围内执行，禁止跨库越权。

## 3. 精简后的对外 API 清单

### 3.1 知识库管理

1. 创建知识库：POST /openapi/v1/knowledge-bases/create
2. 修改知识库信息：POST /openapi/v1/knowledge-bases/update
3. 查询知识库列表：POST /openapi/v1/knowledge-bases/query
4. 查询知识库详情：GET /openapi/v1/knowledge-bases/{kb_id}

### 3.2 知识管理

1. 接入知识源（URL/文件/目录/压缩包）：POST /openapi/v1/knowledge-documents/ingest
2. 启动文档解析：POST /openapi/v1/knowledge-documents/parse
3. 查询解析结果：GET /openapi/v1/knowledge-documents/parse-result/query
4. 获取解析结果下载凭证：GET /openapi/v1/knowledge-documents/parse-result/issue-download-ticket
5. 下载解析结果：GET /openapi/v1/knowledge-documents/parse-result/download
6. 一体化快捷入口（接入并解析）：POST /openapi/v1/knowledge-documents/ingest-and-parse
7. 查询文档信息：GET /openapi/v1/knowledge-documents/{doc_id}

### 3.3 知识索引

1. 构建/重建索引：POST /openapi/v1/knowledge-index/reindex
2. 查询索引任务状态：GET /openapi/v1/knowledge-index/task/query

### 3.4 知识检索

1. 统一检索问答：POST /openapi/v1/knowledge-search/query

### 3.5 编排模式

1. 主流程分开（推荐）：
  - 第一步 `ingest` 负责来源接入与归档。
  - 第二步 `parse` 负责解析执行。
  - 适用于批量、长任务、可重试和强审计场景。
2. 一体化快捷入口（轻量）：
  - `ingest-and-parse` 一次请求完成接入+解析。
  - 适用于单文件、低延迟接入场景。
3. 一体化接口内部仍按两阶段执行，保障可观测性与失败重试。

## 4. 统一协议规范

### 4.1 请求规范

- 协议：HTTPS
- 编码：UTF-8
- 数据格式：JSON（文件上传为 multipart/form-data）
- 鉴权头：Authorization: Bearer {token}
- 追踪头：X-Request-Id（建议必传），可选 X-Trace-Id

入参缺省值策略：
1. 业务参数统一放在请求报文（Body）中，URL 仅作为接口入口，不承载业务参数。
2. 显式配置的字段缺省值优先于系统全局默认值。
3. 可选对象/数组建议采用空对象 `{}` 或空数组 `[]`，避免 `null` 语义歧义。
4. 条件必填字段（如 `kbType=team` 对应 `teamId`）在条件命中时不得使用缺省值兜底，缺失即报错。
5. 更新类接口未传字段按“保持不变”处理，不做隐式清空。

请求方法约定：
1. 写入、触发执行类接口采用 POST。
2. 主动获取、查询任务状态、下载类接口采用 GET。
3. 检索接口统一采用 POST（便于承载复杂检索条件对象）。

接入来源对象约定（`source`）：
1. `source.type=url`：通过外部 URL 抓取文件。
2. `source.type=file`：通过已上传对象（如 objectKey/fileToken）接入。
3. `source.type=directory`：目录接入，服务端递归识别文件列表。
4. `source.type=archive`：压缩包接入，服务端解压并按策略处理子文件。

编排参数约定：
1. `orchestrationMode=split`：仅接入，不自动解析（默认）。
2. `orchestrationMode=quick`：接入完成后自动触发解析。
3. `async=true` 时返回任务 ID；`async=false` 且满足阈值时允许同步返回。

任务状态模型约定：
1. `PENDING`：任务已创建，等待执行。
2. `INGESTING`：接入处理中（抓取/解压/目录扫描）。
3. `INGESTED`：接入完成，待解析。
4. `PARSING`：解析处理中。
5. `SUCCEEDED`：成功完成。
6. `PARTIAL_FAILED`：部分文件失败（目录/压缩包常见）。
7. `FAILED`：执行失败。

幂等与重试约定：
1. 建议请求头或报文中传 `reqId` 作为幂等键。
2. `split` 模式下 `ingest` 与 `parse` 分别幂等，互不影响。
3. `quick` 模式下以单个 `reqId` 覆盖接入+解析全链路幂等。

知识库类型字段约定：
- 字段名：`kbType`
- 可选值：`personal`、`team`、`enterprise`
- 默认值：`personal`
- 约束：`team` 需携带 `teamId`；`enterprise` 建议携带 `orgId` 或租户标识。
- 建议：返回体中统一回传 `kbType`，便于调用方做前端权限显隐与操作拦截。

文档解析能力约定（文件仅解析）：
1. 解析策略参数 `parseStrategy` 定义为对象（来源于 Excel 字段抽象）：

| 对象字段 | 类型 | Excel 对应字段 | 说明 |
| --- | --- | --- | --- |
| parseStrategy.docType | string | 文件类型/扩展名 | 文档类型：pdf/docx/xlsx/pptx/txt/md/html/jpg/png |
| parseStrategy.parseMethod | string | parse_method | 解析方法：auto/ocr/txt |
| parseStrategy.backend | string | backend | 解析引擎：pipeline/vllm-engine |
| parseStrategy.pageRange | array<string> | page_range/pageRange | 页范围，如 ["1","2","4-8"] |
| parseStrategy.chunking.chunkType | string | chunkType | 分段策略：scene/duration/toc/page/line/column/hybrid |
| parseStrategy.chunking.chunkSize | integer | chunkSize | 分段大小 |
| parseStrategy.chunking.chunkOverlap | integer | chunkOverlap | 分段重叠度 |
| parseStrategy.chunking.chunkSplit | string | chunkSplit | 分段分隔符 |
| parseStrategy.chunking.parentChunkSize | integer | chunkBigSize | 父分段大小 |
| parseStrategy.chunking.parentChunkOverlap | integer | chunkBigOverlap | 父子分段重叠 |
| parseStrategy.chunking.parentChunkSplit | string | chunkBigSplit | 父子分段分隔符 |
| parseStrategy.chunking.audioVideoChunkDuration | integer | audioVideoChunkDuration | 音视频分段时长（秒） |
| parseStrategy.enhancement.isAugmented | integer | isAugmented | 是否 LLM 增强：1/0 |
| parseStrategy.enhancement.modelList | array<object> | textModel/picModel/llmPrompt/prompt/hyper_params | 模型配置列表，统一承载模型与提示词 |
| parseStrategy.enhancement.modelList[].modelType | string | - | 模型类型：text/vision/ocr/custom |
| parseStrategy.enhancement.modelList[].modelName | string | textModel/picModel | 模型名称，不传走库默认 |
| parseStrategy.enhancement.modelList[].prompt | string | llmPrompt/prompt | 对应模型提示词 |
| parseStrategy.enhancement.modelList[].hyperParams | object | hyper_params | 对应模型超参 |

2. 返回格式参数 `resultFormat` 定义为对象（来源于 Excel 字段抽象）：

| 对象字段 | 类型 | Excel 对应字段 | 说明 |
| --- | --- | --- | --- |
| resultFormat.type | string | 返回结果类型 | 结果主格式：json/markdown/text |
| resultFormat.includeLayout | boolean | return_layout | 是否返回版面结构 |
| resultFormat.includeInfo | boolean | return_info | 是否返回解析元数据 |
| resultFormat.includeContentList | boolean | return_content_list | 是否返回结构化内容列表 |
| resultFormat.includeImages | boolean | return_images | 是否返回图片信息 |
| resultFormat.imageEncoding | string | return_base64 | 图片编码：url/base64 |
| resultFormat.includeMdLayout | boolean | return_md_content_layout | markdown 是否带 layout |
| resultFormat.persistIntermediate | boolean | is_json_md_dump | 是否保存中间解析产物 |

3. 按文档类型的默认解析策略（抽象层）：

| 文档类型 | 默认 parseMethod | 默认 chunkType | 默认 resultFormat.type | 说明 |
| --- | --- | --- | --- | --- |
| pdf/docx/pptx | auto | page | json | 版面与页结构优先 |
| xlsx | txt | hybrid | json | 表格/多维组合优先 |
| txt/md/html | txt | line | text | 纯文本结构优先 |
| jpg/png | ocr | page | markdown | OCR 与图片内容优先 |

4. 执行方式（`executeMode`）：
  - `sync`：请求内直接返回解析结果（适合小文件）。
  - `async`：返回任务 ID，后续轮询并通过下载接口获取完整结果（适合大文件）。
5. 下载凭证：
  - 先调用 `issue-download-ticket` 获取短期凭证。
  - 再调用 `parse-result:download` 携带凭证下载结果文件。

### 4.2 统一返回体

```json
{
  "traceId": "17857506827185284640327",
  "errCode": "000000",
  "errMsg": "success",
  "data": {}
}
```

### 4.3 错误码建议

| 错误码 | 含义 |
| --- | --- |
| 000000 | 成功 |
| 100001 | 参数错误 |
| 100401 | 未认证或认证失败 |
| 100403 | 无权限访问 |
| 100404 | 资源不存在 |
| 100429 | 请求频率超限 |
| 200001 | 解析失败 |
| 200002 | 索引任务失败 |
| 200003 | 解析结果尚未就绪 |
| 200004 | 下载凭证无效或已过期 |
| 200005 | 来源接入失败（URL/目录/压缩包处理失败） |
| 200006 | 压缩包解压失败或超出安全阈值 |
| 300001 | 检索执行失败 |
| 999999 | 系统内部错误 |

## 6. 推荐落地顺序

1. 先发布 11 个精简对外 API（本方案范围）。
2. 内部保留原有细粒度接口，仅在网关后编排，不对外文档化。
3. 用统一错误码、统一鉴权、统一审计替代“按模块各自定义”。
4. 对外文档默认只维护本 V2 精简版，减少后续接口治理成本。
