## 2. 高优先级（行为/文档严重不符）

1. **文档域 quick 分支状态硬编码** — `app/services/document.py:191`：`record.status=PARSING`（173 行）但响应硬编码 `taskStatus=INGESTED`，与 schema/README 语义不符；现有测试仅覆盖默认 split 未暴露。建议返回 `record.status` 并补测试。
2. **V2 B-07 文档滞后** — `docs/开放平台接口详细定义_精简版_V2.md:893-894`：仍标注「预占位 501001」且无出参字段表，但 `GET /api/v1/knowledge-documents/{doc_id}` 已真实实现（`DocumentInfoResponse`/`DocumentInfoData`）。建议按代码补全出参并移除占位说明。

## 3. 中优先级

### 知识库域（基准自查）
- **A-02 文档与实现不一致**（`V2:264-268` vs `app/schemas/knowledge_base.py:115-118` + `app/services/knowledge_base.py:132-140`）：文档称 update 的 `kbType/visibility/teamId/orgId` 缺省「保持不变」，实现默认 `personal/private/""` 且 service 直接应用 → 缺省即重置，属真实行为陷阱。建议以代码为准修正文档并注明「需显式传当前值」，或实现真局部更新。

### 文档域
- `ingest_and_parse` sync 分支 `resultInline` 恒 `{}`、`taskStatus=PARSING`（`services/document.py:243`），B-06 承诺 sync 内联结果 → 静默空成功；建议标注占位或对未实现分支返回 `501001`。
- `DocumentIngestData` 无 `parseTaskId`（`schemas/document.py:136`）：`orchestrationMode=quick` 进入 PARSING 但调用方拿不到解析任务入口；建议 quick 分支返回 `parseTaskId` 或降级为不自动触发。
- `DocumentErrorCodes.INGEST_FAILED` 全仓零使用（`error_codes.py:110-115`），同 KB `200001/200002` 残留；建议实际使用或标注预留。

### 解析域
- `DocumentParseResponse.data` 为裸 `dict`（`schemas/parse.py:71`），违背「data 为明确字段模型」范式；建议新增 `DocumentParseData(taskId/taskStatus/executeMode/resultInline)`。
- V2 B-03/B-04/B-05 文档列 `kbId` 必填及 `taskId/resultFormat/expireSeconds`，代码仅 `docId(alias)/ticket` → 文档与代码不一致，建议以代码为准同步文档。
- 请求体 `kbId` 声明必填但 service 全程未引用（`services/parse.py:80`），未与 `doc.kb_id` 比对；建议校验归属，防越库。
- 下载接口占位返回 `000000`（`schemas/parse.py:96` note 说明），与「未实现必须 501001」存在张力；README 已标注故非静默，建议契约明确豁免或改 `501001`。
- `tests/test_parse.py` 无参数校验（100001）用例；KB 范式均有覆盖。

### 检索域
- `POST /api/v1/knowledge-search/query` 裸装饰器（`routers/search.py:28-29`），缺 `summary/description/response_model`；落地时必须补 `SearchQueryResponse(data: SearchQueryData)`。
- `payload: SearchQueryRequest | None = None`（`routers/search.py:30`）：空 body 静默转空对象，与 KB 必填入参语义偏差；落地时改必填。
- schema 与 D-01 目标态未双向对齐：代码 `query/kbId/kbIds/ownerId/orgPath` vs D-01 `kbId(必填)/teamId/orgId/mode/topK/filters/withCitation`；落地时文档补 ownerId/orgPath、代码补 D-01 字段。
- 检索路由行为无端到端测试（仅策略引擎单元用例）；缺「带鉴权调检索返回 501001」「路由注入 kb_ids 上下文」用例。

## 4. 低优先级

- `app/core/exception_handlers.py:20`：参数校验错误 `data={"detail": exc.errors()}` 为 `dict[str, list]`，与 KB 错误响应 `dict[str,str]` 范式不一致（全域影响）。
- `app/core/responses.py` 无 `document_*` 响应函数（成功响应在 service 内联，注释「待迁移」）；建议收敛对齐 KB。
- V2 B-06 入参表缺 `docTitle/tags/metadata/orchestrationMode`，出参样例缺 `taskStatus`。
- V2 文档错误码表未同步解析域 `200003/200004/200011`。
- 错误码编号跨域交错：KB `200001/200002`、解析 `200003/200004`、文档 `200010`、解析 `200011`；建议明确分段规则（域内连续）。
- `app/core/authz/runtime.py:59,83` 内置角色映射无 parse 域权限（`km_reader` 仅 `search:query`，无 `document:read/parse:read`）；AUTHZ 开启后语义不一致，建议映射补 `parse:*`。
- 检索路由未按范式调用 `_request_identity(request)`，`ownerId/orgPath` 直接取自载荷（无越权绕过，但与身份派生范式不一致）。
- `tests/test_document.py` 缺 `GET /{doc_id}` 的 403/401、quick/sync 分支用例。
- 文档域 `directory/archive` 来源仅登记单文档（`docIds=[1 项]`、`sourceStats total=1`）伪展开，README 却称「已真实落地」；建议标注占位或实现展开。
- V2 A-02 出参样例 `createTime: null` 与实际（保留原创建时间）不符。
- `SearchErrorCodes` 未建（`SearchException` 已定义）：占位期可接受，落地检索前补建。

## 6. 核查基准（供后续对齐）

1. 路由：summary + description + response_model 三件套；`_request_identity` 派生身份；`authorize_or_raise` 注入 resource_id 与数据上下文。
2. schema：中文 Field 说明 + 默认值 + 条件必填 model_validator + example；响应 `data` 为明确字段模型。
3. 响应：统一壳 + camelCase + UTC ISO；未实现能力 501001（禁静默空成功）。
4. 错误码：进 registry、实际使用、/api/error-codes 可见；编号按域连续。
5. catalog.py 与路由严格同步；V2 文档与代码一致（代码优先）；README 进度同步；行为改动补测试。
