## 4. 专项二：数据结构设计计划

### 4.1 主库环境口径（定稿：SQLite 本地测试 / PostgreSQL 集成测试）

> **结论**：按环境分工——**SQLite 只用于本地开发与单元测试**，**PostgreSQL 用于集成测试、联调、预发与生产**；两环境共用同一套 SQLAlchemy 模型与迁移脚本，业务代码中**不得出现方言分支**。

| 环境 | 数据库 | 配置项 | 用途 | 隔离方式 | 是否需要外部服务 |
| --- | --- | --- | --- | --- | --- |
| 本地开发（dev） | SQLite | `OPEN_PLATFORM_DB_PATH=data/ikc_open_platform.db`（现状默认） | 单人开发、快速验证、调试 | 本地文件（`data/` 已 gitignore） | 否 |
| 单元测试（unit） | SQLite | `OPEN_PLATFORM_DB_PATH=<tmp_path>/test_platform.db` | `pytest tests -q` 默认路径，CI 快速门禁 | 每个用例临时 DB（`tests/conftest.py` autouse 隔离） | 否 |
| 集成测试（integration） | PostgreSQL 16 | `OPEN_PLATFORM_DB_DSN=postgresql+psycopg://ikc_platform:***@127.0.0.1:5432/ikc_platform_test`（待引入） | 真实 SQL 语义、事务与并发、约束、迁移、聚合查询 | 独立测试库 + 事务回滚或按用例重建 schema | 仅 PostgreSQL 容器 |
| 联调 / 预发 / 生产 | PostgreSQL 16 | 同上（独立实例与账号，密钥走环境变量） | 端到端联调、交付、运行态 | 独立实例 + 备份 + 迁移流水线 | 是 |

**配套约束（8 条）**

1. **单一模型**：`app/core/db/models.py` 为唯一 ORM 模型来源，两环境共用；业务代码禁止 `if dialect == "sqlite"` 之类的分支。
2. **方言中立**：不使用 SQLite 专属语法（`INSERT OR REPLACE`、`AUTOINCREMENT`、`PRAGMA` 等）；JSON / 大字段统一用 SQLAlchemy 通用类型（PG 侧落 `JSONB`）；聚合查询避免依赖 SQLite 特有函数。
3. **时间与并发**：统一 UTC 存储；SQLite 单写锁在 PG 侧转为连接池 + 事务隔离，写入并发用例进集成测试。
4. **两类存储分离**：平台控制面库（`OPEN_PLATFORM_DB_PATH` / `OPEN_PLATFORM_DB_DSN`：应用 / 凭证 / 实例 / 配额 / 审计 / 统计 / 管理 token）与实例侧业务库（ikc-core-service + PostgreSQL）互不复用连接与事务。
5. **单测不得依赖 PostgreSQL**：需要 PG 的用例打 `@pytest.mark.integration`，默认 `pytest tests -q` 不执行。
6. **集成测试必须覆盖**：建表 / 迁移的双向执行；唯一约束冲突（`api_keys.key_hash`、`instances` 实例 ID、`apps` 应用 ID）；审计与统计聚合的并发写入；`audit_log` / `request_stats` 分页与排序稳定性。
7. **版本一致**：集成测试、联调、生产同为 PostgreSQL 16；SQLite 与 PG 的行为差异由集成测试兜住，不在业务代码里兜。
8. **阶段一出口口径（M0 验收）**：SQLite 单测全绿 + PostgreSQL 集成测试全绿 + 建表 / 迁移双向可执行 + 两环境表结构一致。

## 9. 风险与依赖

| 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- |
| 限流配额为进程内内存实现 | 多副本不共享、重启归零、配额不可信 | 阶段一迁移 Redis / DB；先按单副本部署并文档标注 |
| 日配额计数口径（仅 QPS 通过后自增） | 被 QPS 拒绝的请求不计日额度，额度统计偏低 | 阶段一修正计量口径并补用例 |
| 两条占位接口（`upload`、`issue-download-ticket`） | 文档上传与产物下载链路不可用 | 阶段一优先清零，未完成前在手册与契约中标注「待定义」 |
| `parse-result/download` 以 GET 携带 body | 兼容性依赖实例 / httpx 行为，存在失败风险 | 阶段一验证；必要时改为 POST 或 query 参数并同步契约 |
| 数据库仅 SQLite + `create_all`，无迁移工具 | 生产 PostgreSQL 切换与结构演进困难 | 阶段一引入迁移工具与 PostgreSQL 集成测试 |
| SQLite 与 PostgreSQL 行为差异（大小写、唯一约束、并发、聚合） | 单测通过但联调失败 | §4.1 方言中立 + `@pytest.mark.integration` 门禁 |
| SDK 制品版本不一致（dist 0.1.0 / pyproject 0.2.0） | 使用方拿到旧版 | 阶段一重打包 + 发布流水线 + 版本校验 |
| `oidc_jwt` / `oauth2_introspection` 未实现 | 生产环境只能依赖网关注入身份 | 阶段二实现并完成 IdP 联调；生产禁用 `static` |
| 宿主端口占用（容器内 18000 回环 + HAProxy 8080） | 对外暴露方式未定，联调入口不统一 | 阶段一定稿入口与端口方案，文档化 |
| 图数据库 / 图库选型未定 | 图谱索引与多跳检索无法落地 | 阶段二 PoC 后定稿 |
| 契约缺口（G0–G11）与 wiki / graph 域模型缺失 | 开放新能力时返工 | 契约评审与 `ikc-sdk-lib` 版本节奏并行推进 |
