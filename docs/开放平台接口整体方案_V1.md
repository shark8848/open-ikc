> 文档生成日期：2026-08-03

## 1. 建设目标

本方案面向企业级智能知识库开放平台，目标是将现网接口统一为可治理、可扩展、可审计的北向能力面。

核心目标：
1. 对业务系统、数字员工、合作伙伴提供一致的调用契约。
2. 将知识管理、RAG、模型、解析、治理能力分层开放。
3. 在全链路落实权限不降级、证据可追溯、审计可回放。

## 4. 统一开放规范

### 4.1 协议与编码
- 传输协议：HTTP/HTTPS。
- 编码：UTF-8。
- 数据格式：JSON 为主，二进制文件走文件流或分片。

### 4.2 鉴权与身份
- 支持 appid + appKey、token、会话标识。
- 用户身份与 Agent 身份分离，权限独立核算。
- 默认拒绝，显式授权后访问。

### 4.3 返回体约定
- 建议统一返回：status、errCode、errMsg、data。
- 成功与失败应统一错误码字典，便于调用侧编排与重试。

### 4.4 幂等与一致性
- 新增/编辑接口建议支持业务幂等键（如 req_id、task_id）。
- 写操作审计必落库，记录主体、时间、参数摘要、结果。

### 4.5 安全与治理
- 权限不降级：接入、索引、检索、生成、工具调用全链路执行权限。
- 支持租户/组织/工作空间/文档/字段分级控制。
- 敏感字段脱敏与审计追踪。

## 5. 典型调用链路

### 5.1 文档入库与索引
文件上传（J） → 解析转换（G） → 元数据绑定（A） → 分段切片（E） → 知识对象入库（B） → 缓存刷新（H）

### 5.2 检索问答与开放调用
身份鉴权（统一） → 检索工具调用（I） → 权限过滤（治理） → 证据返回与追踪（审计）

### 5.3 Agent 行动链路
上下文组装 → 检索/规则校验 → 高风险审批 → 业务执行 → 行动依据记录

## 6. 与 6.5 规划映射

| 规划方向 | 接口方案落点 |
| --- | --- |
| RAG 组件化 | G/E/H/I 形成解析-索引-检索原子能力 |
| 开放平台能力补齐 | I（开放调用）+ J（文件）+ F（模型） |
| 统一认证鉴权 | 统一鉴权规范与 Header 策略 |
| 知识管理+RAG 3.0 | A/B/K 与 RAG 域耦合形成中台能力 |

## 7. 发布与版本建议

1. 版本策略：路径版本化（如 /v1/）或 Header 版本。
2. 兼容策略：新增字段向后兼容，删除字段需跨版本。
3. 灰度策略：按租户/应用白名单分批开放。
4. 可观测性：接口级 QPS、P95、错误码、权限拒绝率、审计完整度。
