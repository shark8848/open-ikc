# 开放平台接口详细定义（精简版 V2）

> 文档生成日期：2026-08-03
> 范围：仅保留 4 大对外能力域（知识库管理、知识管理、知识索引、知识检索）

## A. 知识库管理

### A-00 知识库类型规则

定义：对外知识库统一支持 `personal`、`team`、`enterprise` 三种类型。

| 类型 | 说明 | 关键校验 |
| --- | --- | --- |
| personal | 个人知识库 | 当前用户必须为库创建者 |
| team | 团队知识库 | 必须提供 teamId，且调用方属于团队 |
| enterprise | 企业知识库 | 建议提供 orgId，且调用方在企业授权范围内 |

统一约束：
1. 若知识库类型与调用主体权限不匹配，返回 `100403`。
2. 若 `team` 类型缺少 `teamId`，返回 `100001`。
3. 若 `enterprise` 类型无组织授权，返回 `100403`。

错误码体系：

| 错误码 | 层级 | 含义 | 适用范围 |
| --- | --- | --- | --- |
| 000000 | 成功 | 请求处理成功 | 所有接口 |
| 100001 | 参数层 | 请求参数缺失、类型错误或校验失败 | 所有接口 |
| 100401 | 认证层 | 未认证或认证失败 | 所有接口 |
| 100403 | 鉴权层 | 无权限或越权访问 | 所有接口 |
| 100404 | 资源层 | 目标资源不存在 | 所有接口 |
| 100405 | 框架层 | 请求路径存在但 HTTP 方法不被支持 | 所有路由 |
| 100409 | 冲突层 | 资源冲突、重复创建或状态冲突 | 所有写接口（创建/更新/接入） |
| 200001 | 业务层 | 创建知识库失败 | 知识库创建接口 |
| 200002 | 业务层 | 修改知识库失败 | 知识库修改接口 |
| 200003 | 业务层 | 解析结果尚未就绪 | 解析结果查询 / 下载凭证签发接口 |
| 200004 | 业务层 | 下载凭证无效或已过期 | 下载接口 |
| 200010 | 业务层 | 接入知识源失败 | 文档接入接口 |
| 200011 | 业务层 | 解析失败 | 文档解析接口 |

异常继承与传递约定：

1. 业务层优先抛 `AppException` 或其子类，知识库领域可使用 `KnowledgeBaseException`。
2. 推荐通过错误码对象生成异常，例如 `error.as_exception(...)` 或统一工厂方法，避免在业务层手写返回体。
3. `ErrorCode.message` 作为默认错误描述，必要时可在抛出时覆盖 `message`，但错误码本身不变。
4. `AppException` 进入 API 层后统一转换为 `{errCode, errMsg, data}` 响应体。
5. 参数校验异常统一收敛到 `100001`，认证/鉴权/资源/冲突类异常分别收敛到 `100401/100403/100404/100409`。
6. `501001` 作为框架占位错误码，仅用于未实现接口，不建议业务正式态继续沿用。

TraceID 约定：

1. 所有接口请求会注入 23 位纯数字 `traceId`。
2. 优先读取请求头 `X-Request-Id`、`X-Trace-Id`、`traceId`、`trace_id`。
3. 响应头回写 `X-Request-Id` 和 `X-Trace-Id`，响应体顶层统一带 `traceId`。
4. 日志上下文由 `ikc-log-center` SDK 承接，便于在日志中心按链路检索。

错误码使用示例：

```python
from app.core.error_codes import CommonErrorCodes, exception_from_code

raise CommonErrorCodes.FORBIDDEN.as_exception(
  {"scope": "knowledge-base"},
  message="无权限访问当前知识库",
)

raise exception_from_code(
  CommonErrorCodes.INVALID_PARAMS,
  {"field": "kbId", "reason": "不能为空"},
)
```

错误码查询示例：

```python
from app.core.error_codes import BaseErrorCodes, error_code_catalog

error = BaseErrorCodes.get_by_code("100403")
catalog = error_code_catalog()
```

在线错误码目录：

- 接口：`GET /api/error-codes`
- 返回：`{status, data, traceId}`，其中 `data` 为错误码对象数组，字段包含 `code`、`message`、`level`、`description`

### A-01 创建知识库

- 方法：POST
- 路径：/openapi/v1/knowledge-bases/create
- 定义：创建新的知识库并返回库标识。
- 描述：用于初始化一个可接收文档、可构建索引、可执行检索的知识库。知识库类型支持个人、团队、企业。

请求体说明：

| 字段 | 类型 | 必填 | 默认值 | 详细说明 |
| --- | --- | --- | --- | --- |
| kbName | string | 是 | 无 | 知识库名称，面向用户展示，需在同一组织/租户内尽量唯一。 |
| kbType | string | 否 | personal | 知识库类型：personal 个人库、team 团队库、enterprise 企业库。若选择 team 或 enterprise，后续权限与可见范围将按类型收敛。 |
| kbMode | string | 否 | text | 知识库形态：text 文本库（默认）、wiki Wiki 库（页面树）、graph 图谱库（实体关系网）。与 kbType 正交，任一归属类型可叠加任一形态。 |
| teamId | string | 否 | "" | 团队知识库标识；当 kbType=team 时必填，用于校验团队归属和调用者是否属于该团队。 |
| orgId | string | 否 | "" | 企业知识库组织标识；当 kbType=enterprise 时建议填写，用于租户隔离、组织授权和检索范围控制。 |
| kbDesc | string | 否 | "" | 知识库描述，用于说明业务场景、使用边界和维护责任。 |
| bizDomain | string | 否 | general | 业务域标签，例如 hr、finance、customer_service，用于前端分类和后续治理统计。 |
| visibility | string | 否 | private | 可见范围：private 表示仅创建者或授权范围内可见，org 表示组织内共享。 |
| metadataSchema | array<object> | 否 | [] | 元数据字段定义列表，用于约束知识库录入字段、检索过滤条件和权限标签。 |
| wikiConfig | object | 否 | {} | Wiki 库配置（kbMode=wiki 时生效）：granularity(auto/heading/section/page)、extractFields[]、linkMode(auto/off)、dedup(merge/overwrite/skip)、template。 |
| graphSchema | object | 否 | {} | 图谱库配置（kbMode=graph 时生效）：entityTypes[{type,description}]、relationTypes[{type,sourceTypes[],targetTypes[],description}]；类型必填且不重复。 |

条件校验规则：

1. 当 `kbType=team` 时，`teamId` 必填，且调用方必须属于对应团队。
2. 当 `kbType=enterprise` 时，`orgId` 建议填写；若平台侧未能通过调用主体识别组织授权，应返回 `100403`。
3. `visibility=org` 时，知识库结果默认按组织内授权范围可见，仍需结合调用主体权限过滤。
4. `kbMode=wiki` 与 `kbMode=graph` 之间不支持直接互转（修改库形态时返回 `200014`）；text 与 wiki、text 与 graph 可双向切换。

`metadataSchema[]` 对象说明：

| 字段 | 类型 | 必填 | 默认值 | 详细说明 |
| --- | --- | --- | --- | --- |
| name | string | 是 | 无 | 元数据字段名，建议使用英文或拼音标识，需在同一知识库内唯一。 |
| type | string | 是 | 无 | 字段类型：string、number、integer、boolean、date、datetime、enum、object。 |
| required | boolean | 否 | false | 是否必填。为 true 时，后续文档录入或补充时必须提供。 |
| description | string | 否 | "" | 字段业务含义说明，建议写明用途、口径和使用边界。 |
| defaultValue | any | 否 | null | 默认值；当调用方未传该字段时可采用此值。 |
| enum | array<string> | 否 | [] | 枚举值集合；当 type=enum 时建议填写，便于前端下拉展示和后端校验。 |
| pattern | string | 否 | "" | 正则约束，适用于字符串类字段的格式校验。 |
| minLength | integer | 否 | null | 字符串最小长度。 |
| maxLength | integer | 否 | null | 字符串最大长度。 |
| example | any | 否 | null | 字段示例值，用于文档展示和联调参考。 |

`visibility` 取值说明：

| 取值 | 说明 |
| --- | --- |
| private | 私有可见，仅创建者或显式授权范围内可访问。 |
| org | 组织可见，组织内授权用户可访问。 |

条件校验规则同 A-01。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| kbName | string | 是 | 无 | 知识库名称 |
| kbType | string | 否 | personal | 知识库类型：personal/team/enterprise |
| teamId | string | 否 | 无 | 当 kbType=team 时必填 |

| visibility | string | 否 | private | 可见范围，private/org |

### A-02 修改知识库信息

- 方法：POST
- 路径：/openapi/v1/knowledge-bases/update
- 定义：更新知识库基础信息。
- 描述：用于调整知识库名称、类型、描述、可见范围和元数据配置。

请求体说明：

| 字段 | 类型 | 必填 | 默认值 | 详细说明 |
| --- | --- | --- | --- | --- |
| kbId | string | 是 | 无 | 知识库 ID，更新操作的唯一定位标识。 |
| kbName | string | 否 | 保持不变 | 新名称；传空字符串表示不修改。 |
| kbType | string | 否 | personal | 知识库类型；**未显式传入时按默认值 personal 重置**，如发生变更需同步校验 teamId/orgId 与权限边界。 |
| teamId | string | 否 | "" | 团队知识库标识；**未显式传入时清空**。 |
| orgId | string | 否 | "" | 企业知识库组织标识；**未显式传入时清空**。 |
| kbDesc | string | 否 | 保持不变 | 知识库描述；传空字符串表示不修改。 |
| visibility | string | 否 | private | 可见范围；**未显式传入时按默认值 private 重置**。 |
| metadataSchema | array<object> | 否 | 保持不变 | 元数据字段定义列表；为空时表示保持不变。 |

`metadataSchema[]` 对象说明同 A-01。

> 注意：`kbType`/`teamId`/`orgId`/`visibility` 为全量语义字段，缺省会被平台按默认值重置；仅更新名称/描述时也需显式回传这四个字段的当前值（官方 SDK 的 `update()` 会自动拉取现有记录合并，避免误重置）。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| kbId | string | 是 | 无 | 知识库 ID |
| kbName | string | 否 | 保持不变 | 新名称 |
| kbType | string | 否 | personal | personal/team/enterprise（未显式传入时按默认值重置） |
| teamId | string | 否 | "" | 当 kbType=team 时必填（未显式传入时清空） |
| orgId | string | 否 | "" | 当 kbType=enterprise 时建议填写（未显式传入时清空） |
| kbDesc | string | 否 | 保持不变 | 新描述 |
| visibility | string | 否 | private | private/org（未显式传入时按默认值重置） |
| metadataSchema | array<object> | 否 | 保持不变 | 元数据定义 |

出参：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| errCode | string | 错误码 |
| errMsg | string | 错误信息 |
| data.kbId | string | 知识库 ID |
| data.kbName | string | 知识库名称 |
| data.kbType | string | 知识库类型 |
| data.teamId | string | 团队知识库标识 |
| data.orgId | string | 企业知识库组织标识 |
| data.kbDesc | string | 知识库描述 |
| data.bizDomain | string | 业务域标签 |
| data.visibility | string | 可见范围 |
| data.metadataSchema | array<object> | 元数据字段定义列表 |
| data.createTime | string | 创建时间（更新时保留原值） |
| data.updateTime | string | 更新时间 |

### A-04 查询知识库列表

- 方法：POST
- 路径：/openapi/v1/knowledge-bases/query
- 定义：按类型、团队/组织范围与关键字分页查询调用方可访问的知识库。
- 描述：列表结果按调用方数据权限收敛：个人库仅返回本人创建，团队库需携带 `teamId`，企业库按 `orgId` 或调用主体租户收敛。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| kbType | string | 否 | 全部 | 按知识库类型过滤：personal/team/enterprise |
| teamId | string | 否 | "" | 查看团队库时必填，用于成员范围收敛 |
| orgId | string | 否 | "" | 查看企业库时建议填写，为空时使用调用主体租户 |
| ownerId | string | 否 | "" | 个人库创建者过滤（个人库始终按调用方身份收敛） |
| keyword | string | 否 | "" | 按名称或描述关键字过滤 |
| page | integer | 否 | 1 | 页码，从 1 开始 |
| pageSize | integer | 否 | 20 | 每页条数，最大 100 |

出参：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| traceId | string | 请求链路追踪 ID |
| errCode | string | 错误码 |
| errMsg | string | 错误信息 |
| data.total | integer | 命中总数 |
| data.page | integer | 当前页码 |
| data.pageSize | integer | 每页条数 |
| data.items | array<object> | 知识库列表（字段同 A-03 data） |

## B. 知识管理

### B-00 接入与解析编排模式

- `split`（推荐）：先 `ingest`，后 `parse`。
- `quick`（快捷）：一次调用 `ingest-and-parse`。

说明：
1. `split` 适用于批量、长任务、可重试场景。
2. `quick` 适用于单文件、低延迟接入场景。
3. `quick` 内部仍按两阶段执行，返回可追踪任务 ID。

### B-01 接入知识源

- 方法：POST
- 路径：/openapi/v1/knowledge-documents/ingest
- 定义：接入知识源并登记到指定知识库。
- 描述：统一支持 URL、文件、目录、压缩包四种来源形态。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| reqId | string | 否 | 自动生成 | 幂等请求标识，建议调用方传入 |

### B-02.1 免库独立解析（场景 B：只要解析能力）

### B-02.2 文档上传暂存（7 天）

- 方法：POST
- 路径：/openapi/v1/knowledge-documents/upload
- 定义：上传单个文档文件，平台暂存 7 天并返回临时访问地址。

### D-02 深度检索

- 方法：POST
- 路径：/openapi/v1/knowledge-search/deep-search
- 定义：在知识库中执行 Agentic 深度检索，返回带引用回答。
- 描述：子查询规划、并行多轮召回、反思与回答生成，面向复杂问题；依赖下游 DeepSearch 能力，未配置 `OPEN_PLATFORM_SEARCH_BACKEND=openai` 或下游未启用时返回 `501001`。权限收敛与 D-01 一致（逐库授权，任一库失败整体拒绝）。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| kbId | string | 是 | 无 | 知识库 ID |
| teamId | string | 否 | 无 | 当目标知识库类型为 team 时建议传入 |
| orgId | string | 否 | 无 | 当目标知识库类型为 enterprise 时建议传入 |
| query | string | 是 | 无 | 复杂检索问题 |
| searchType | string | 否 | hybrid | fulltext/vector/hybrid |
| topK | integer | 否 | 8 | 每轮召回窗口（1~100） |
| useRerank | boolean | 否 | true | 深度检索默认重排 |
| sessionId | string | 否 | 无 | 会话 ID，用于下游记忆检索 |
| memory | object | 否 | 无 | `{mode: caller, items: [...]}` 调用方注入记忆 |
| deepSearch | object | 否 | 服务端默认 | `maxSteps`（默认 5）、`subQuery{enabled,maxSubQueries,mergeStrategy}`、`stopWhen{minEvidence,minFinalScore,maxLatencyMs}`、`recallTopnPolicy`（fixed/adaptive） |
| filters | object | 否 | {} | 元数据过滤条件 |
| responseSpec | object | 否 | include=[answer,citations,usedQueries] | include 支持 answer/citations/usedQueries/steps |

出参：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| traceId | string | 请求链路追踪 ID |
| errCode | string | 错误码 |
| errMsg | string | 错误信息 |
| data.answer | string | 最终回答（带证据编号引用） |
| data.total | integer | 回答引用证据总数（等于 data.citations 长度） |
| data.citations | array<object> | 回答引用证据列表（引用编号 [n] 对应数组下标；docId/docTitle/score/snippet/position/page?） |
| data.usedQueries | array<string> | 实际执行的子查询列表 |
| data.steps | array<object> | Agent 步骤明细（responseSpec.include 含 steps 时返回） |

样例：

```json
{
  "query": "对比 2025 与 2026 产品白皮书的检索能力差异，并给出结论",
  "kbIds": ["kb_10001", "kb_10002"],
  "searchType": "hybrid",
  "deepSearch": {"maxSteps": 5, "subQuery": {"enabled": true, "maxSubQueries": 3}}
}
```

## 附录：当前占位实现说明

1. 四类对外能力（知识库 A / 文档 B-01/B-06/B-07 / 解析 B-02~B-05 / 检索 D-01/D-02）均已真实实现；仅索引能力（C-01/C-02，属后续规划）为预占位。
2. 检索接口（D-01/D-02）已落地：D-01 普通检索支持 `searchType`（fulltext/vector/hybrid）、`topK` 截断（默认 5，上限 100）、`relNum` 关联召回、`useRerank` 重排、`score` 阈值、`filters` 元数据过滤、`withCitation` 控制引用返回；`mode=qa` 时下游不生成回答则返回空 `answer` 并在 `qaNote` 提示使用深度检索（不再返回占位文案，进程内占位后端除外）。D-02 深度检索对接下游 DeepSearch，返回 `answer`/`citations`/`usedQueries`。`OPEN_PLATFORM_SEARCH_BACKEND=in_process`（默认）时普通检索使用进程内关键词匹配（由调用方显式注入，不随 ingest/parse 自动构建）；配置 `ur`/`openai` 后对接 knowledge_transformer 检索能力（`app/services/search_client.py`）。
3. 字段以运行时返回与 `/api/error-codes` 为准；占位接口（索引 C-01/C-02 若临时暴露）通过统一异常链路返回错误码 `501001`，响应体格式为 `{traceId, errCode, errMsg, data}`。
4. 检索数据权限边界：个人知识库（personal）仅创建者可检索，越权返回 `100403`；团队（team）/企业（enterprise）知识库的成员与组织范围收敛依赖 AUTHZ 策略（`owner_id`/`org_path` 由调用方显式传入或默认取调用主体身份），**AUTHZ 关闭（`OPEN_PLATFORM_AUTHZ_ENABLED=false`）时仅校验知识库存在性与个人库归属，team/enterprise 库不额外做成员校验**——生产环境须开启 AUTHZ 并接入真实团队/组织系统。
