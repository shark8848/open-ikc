## 4. 专项二：数据结构设计计划

### 4.1 主库环境口径（定稿：SQLite 本地测试 / PostgreSQL 集成测试）

> **结论**：不做「二选一」，而是**按环境分工**——**SQLite 只用于本地开发与单元测试**，**PostgreSQL 用于集成测试、联调、预发与生产**。两环境共用同一套 SQLAlchemy 模型与 Alembic 迁移，业务代码中**不得出现方言分支**。

| 环境 | 数据库 | 配置项 | 用途 | 隔离方式 | 是否需要外部服务 |
| --- | --- | --- | --- | --- | --- |
| 本地开发（dev） | SQLite | `OPEN_PLATFORM_BIZ_DB_DSN=sqlite:///data/open_ikc_biz.db` | 单人开发、快速验证、调试 | 本地文件（`data/` 已 gitignore） | 否 |
| 单元测试（unit） | SQLite | `OPEN_PLATFORM_BIZ_DB_DSN=sqlite:///{tmp_path}/biz.db` | `pytest tests -q` 默认路径，CI 快速门禁 | 每个用例 `tmp_path` 独立 DB（与现有 `OPEN_PLATFORM_DB_PATH` autouse fixture 同一约定） | 否 |
| 集成测试（integration） | PostgreSQL 16 | `OPEN_PLATFORM_BIZ_DB_DSN=postgresql+psycopg://open_ikc:***@127.0.0.1:5432/open_ikc_test` | 真实 SQL 语义、事务与并发、约束、迁移、索引 | 独立测试库 + 事务回滚或按用例重建 schema | 仅 PostgreSQL 容器 |
| 联调 / 预发 / 生产 | PostgreSQL 16 | 同上（独立实例与账号，密钥走环境变量） | 端到端联调、交付、运行态 | 独立实例 + 备份 + 迁移流水线 | 是 |

**配套约束（8 条）**

1. **单一模型**：`app/services/*` 只依赖 Repository 抽象；SQLAlchemy 模型与 Alembic 迁移两环境共用，禁止 `if dialect == "sqlite"` 之类的业务分支。
2. **方言中立**：不使用 SQLite 专属语法（`INSERT OR REPLACE`、`AUTOINCREMENT`、`PRAGMA` 等），DDL 一律由 Alembic 生成；JSON 统一用 SQLAlchemy `JSON` 类型（PG 侧落 `JSONB`）；全文检索走 ES、向量走 pgvector，**不依赖 SQLite FTS**。
3. **时间与并发**：统一以 UTC 存储；乐观锁统一用 `row_version` 列，并发冲突由 PostgreSQL 集成测试覆盖。
4. **两类库分离**：管理面库（`OPEN_PLATFORM_DB_PATH`，SQLite：token 哈希 / 请求统计）与业务库（`OPEN_PLATFORM_BIZ_DB_DSN`）互不复用连接；管理面**继续保留 SQLite**，不纳入 PG 迁移范围。
5. **单测不得依赖 PostgreSQL**：任何需要 PG 的用例必须打 `@pytest.mark.integration`，默认 `pytest tests -q` 不执行，保证 PG 未启动时也全绿。
6. **集成测试必须覆盖**：Alembic `upgrade` 与 `downgrade` 双向迁移；唯一约束冲突（`knowledge_unit.unit_path`、`wiki_page.page_id`、`kb.kb_id`）；事务回滚与并发计数；JSON 字段读写与 `index_registry` / `doc_index_state` 状态机；分页与排序稳定性。
7. **版本一致**：集成测试、联调、生产必须同为 PostgreSQL 16 大版本；SQLite 与 PG 的行为差异由集成测试兜住，不在业务代码里兜。
8. **阶段一出口口径（M0 验收）**：SQLite 单测全绿 + PostgreSQL 集成测试全绿 + 迁移双向可执行 + 两环境 schema 摘要一致。

**执行命令（落地后照此执行）**

```bash
# 单元测试：SQLite，默认路径，无外部依赖
cd /home/open-ikc && .venv/bin/python -m pytest tests -q

# 集成测试：PostgreSQL 16（容器，镜像 postgres:16-alpine）
docker run -d --name open-ikc-pg -p 5432:5432 \
  -e POSTGRES_USER=open_ikc -e POSTGRES_PASSWORD=open_ikc -e POSTGRES_DB=open_ikc_test \
  postgres:16-alpine
export OPEN_PLATFORM_BIZ_DB_DSN="postgresql+psycopg://open_ikc:open_ikc@127.0.0.1:5432/open_ikc_test"
.venv/bin/python -m pytest tests -q -m integration
```

> 待补（阶段一 P1）：`docker-compose.yml` 增加 `postgres:16-alpine` 服务 + `open_ikc_test` 库初始化脚本 + CI 两段式流水线（先 unit@SQLite，再 integration@PostgreSQL）。

## 9. 风险与依赖

| 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- |
| `content_document` 格式（自研 block vs MinerU / DocJSON）未定稿 | 解析 → 切片 → 索引链路返工，M1 无法开工 | 阶段一首周完成评审定稿，写入本计划与 `process.md` |
| SQLite 与 PostgreSQL 行为差异（大小写敏感、唯一约束、并发、JSON、排序） | 单测通过但联调失败 | §4.1 方言中立 + `@pytest.mark.integration` 集测门禁，差异只由集测兜 |
| 集成测试依赖 PostgreSQL 容器（镜像 / 端口） | 集测无法纳入 CI | 固定 `postgres:16-alpine` + compose 服务，CI 两段式（unit@SQLite → integration@PG）；镜像不可达时用本地已有镜像 |
| 真实解析引擎产物结构与 `content_template` 不匹配 | 解析 → 切片 → 索引链路返工 | 先冻结模板 schema，再做引擎适配层 |
| async 任务缺 worker，`executeMode=async` 语义不可信 | 对外承诺的异步能力失效 | 阶段一优先落地 worker + 任务查询接口，未完成前文档明确标注 |
| 引擎侧统一响应壳未对齐（PyUploadX / ikc_extraction / knowledge_transformer） | 网关层需做适配，错误码语义不统一 | 在适配层收敛，禁止把差异透出到对外协议 |
| 图谱 LLM 成本与开关未决策（`process.md` §3） | 图谱加工成本不可控 | 产品确认默认值与配额后再启用 `extraction=llm` |
| SDK 制品无发布链路 | 三方接入只能源码集成 | 阶段一建私有 index / Maven 仓与发布流水线 |
| 契约缺口 G0–G11（traceId 位宽、状态字面量等） | 跨服务联调返工 | 阶段一完成契约 v0.4 归一 |
| 网络 / 镜像仓库可达性（docker.io 等） | 重建镜像受阻 | 保留环境变量注入方案，需要重建时先恢复网络 |
