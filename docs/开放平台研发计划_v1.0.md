# IKC 开放平台研发计划 v1.0（分层 · 组件 · SDK · 引擎 · 数据与接口 · 对接联调）

> **输入依据**：`docs/images/开放平台架构总图_v1.0.svg`（图内版本 v6.0，六层 + 治理与运营横切）、`AGENTS.md`、`docs/开放平台接口整体方案_V2_精简.md`、`docs/开放平台接口详细定义_精简版_V2.md`、`docs/知识运营数据模型总体设计方案.md`（v2.3）、`docs/全局契约_跨层共享模型与协议_v0.3.md`、`process.md`、`docs/worklog.md`。
> **时间口径**：本计划按 **2 个阶段** 编排——**阶段一（9 月）**、**阶段二（10 月）**；时间列以 `__/__ – __/__` 占位，由项目自行填写具体日期。
> **优先级**：P0 阻塞关键路径 / P1 高 / P2 中 / P3 低。
> **范围**：图中显性块 + 图中未显性但已由 `process.md`、数据模型方案、全局契约记为缺口的组件（限流与配额、PipelineRun 任务对象、配置中心、评测、内容合规、文档采集器连接器、JavaScript/TypeScript SDK、SDK 制品发布链路、本体引擎服务面）。
> **表格用法**：§1 为全平台一页纸总览；§2 为按层明细（层 → 子系统/组件 → 组件之下 SDK → Service 引擎 → 研发内容 → 现状 → 优先级 → 阶段 → 时间 → 交付物）；§3–§6 为 SDK、数据结构、接口、对接联调四个专项；§7 为阶段里程碑。

## 9. 风险与依赖

| 风险 / 依赖 | 影响 | 应对 |
| --- | --- | --- |
| 主库（SQLite vs PostgreSQL）与 `content_document` 格式未定稿 | M0 / M1 无法开工，阶段一整体顺延 | 阶段一首周完成评审定稿，写入本计划与 `process.md` |
| 真实解析引擎产物结构与 `content_template` 不匹配 | 解析 → 切片 → 索引链路返工 | 先冻结模板 schema，再做引擎适配层 |
| async 任务缺 worker，`executeMode=async` 语义不可信 | 对外承诺的异步能力失效 | 阶段一优先落地 worker + 任务查询接口，未完成前文档明确标注 |
| 引擎侧统一响应壳未对齐（PyUploadX / ikc_extraction / knowledge_transformer） | 网关层需做适配，错误码语义不统一 | 在适配层收敛，禁止把差异透出到对外协议 |
| 图谱 LLM 成本与开关未决策（`process.md` §3） | 图谱加工成本不可控 | 产品确认默认值与配额后再启用 `extraction=llm` |
| SDK 制品无发布链路 | 三方接入只能源码集成 | 阶段一建私有 index / Maven 仓与发布流水线 |
| 契约缺口 G0–G11（traceId 位宽、状态字面量等） | 跨服务联调返工 | 阶段一完成契约 v0.4 归一 |
| 网络 / 镜像仓库可达性（docker.io 等） | 重建镜像受阻 | 保留环境变量注入方案，需要重建时先恢复网络 |
