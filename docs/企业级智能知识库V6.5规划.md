# 文档目的
本文用于定义企业级智能知识库的核心概念、业务范围、能力边界和体系框架，为企业开展智能知识库规划、平台建设、场景落地及运营治理提供统一参考。

企业级智能知识库不是单一的软件产品，也不等同于文档库、向量数据库、知识图谱或大模型问答系统，而是一套连接企业知识、数据、人员、业务系统和 AI Agent 的知识基础设施。

# 智能知识库概念
## 定义
:::info
企业级智能知识库，是以企业权威知识和业务数据为事实基础，以企业本体为语义骨架，以知识图谱、LLM Wiki 和多类型索引为持久化知识表达，以全文检索、RAG、GraphRAG、SQL及业务API为证据获取机制，以大语言模型和AI Agent为理解、推理及行动引擎，并通过权限、溯源、版本、审核、评测和生命周期管理实现持续治理的企业知识基础设施。

:::

其核心目标是将分散在文档、数据库、业务系统及人员经验中的知识，转化为：

+ 可发现；
+ 可理解；
+ 可关联；
+ 可验证；
+ 可复用；
+ 可计算；
+ 可治理；
+ 可供人、应用和AI Agent共同使用的企业知识资产。

## 核心定位
:::info
企业级智能知识库在企业数字化架构中属于统一的**知识与上下文层（Knowledge and Context Layer）**，位于数据和业务系统之上、智能应用和AI Agent之下。

:::

```latex
员工、客户、合作伙伴、业务应用、AI Agent
                    │
                    ▼
           智能知识与上下文服务
                    │
                    ▼
文档系统、数据平台、业务系统、互联网及专家知识
```

智能知识库不只是回答“文档中写了什么”，还需要支持：

1. 企业如何定义某个业务概念；
2. 不同系统中的概念是否表示同一对象；
3. 某项结论依据哪些原始证据；
4. 某条知识在什么时间、组织和产品范围内有效；
5. 多份资料存在冲突时应如何处理；
6. 当前业务对象的实时状态是什么；
7. AI Agent在完成任务时可以使用哪些知识和工具；
8. 用户和Agent在什么权限范围内可以访问及执行操作。

## 核心特征
企业级智能知识库应具备以下基本特征：

| 特征 | 说明 |
| --- | --- |
| 权威性 | 明确知识来源、责任主体、审核状态和权威等级 |
| 语义一致性 | 通过本体、术语体系和语义模型统一业务概念 |
| 可验证性 | 答案和结论能够回溯至原始文档、数据或业务接口 |
| 实时性 | 根据知识类型采用定时同步、事件更新或实时查询 |
| 权限一致性 | 检索权限不超过用户在源系统中的原有权限 |
| 多模态性 | 支持文本、表格、图片、音频、视频、代码和结构化数据 |
| 可推理性 | 支持实体关系、多跳检索、规则判断和复杂问题分解 |
| 可运营性 | 支持知识审核、版本、反馈、评测、监控和持续优化 |
| 可服务化 | 以搜索、问答、API、MCP或Agent工具等方式提供能力 |
| 可扩展性 | 能够服务多个部门、业务应用和AI Agent |


# 核心概念及其关系
## 企业知识本体
:::info
企业知识本体是对业务领域中概念、类型、属性、关系、约束和规则的统一定义。

:::

本体主要回答：

+ 企业中存在哪些业务对象；
+ 对象之间具有什么关系；
+ 每类对象具备哪些属性；
+ 不同系统中的术语如何映射；
+ 哪些关系和状态转换是合法的；
+ 哪些业务规则及数据约束必须满足。

例如：

```latex
客户 --签订--> 合同
合同 --包含--> 产品
产品 --包含--> 物料
物料 --来源于--> 供应商
供应商 --具有--> 风险等级
合同 --受约束于--> 合规条款
```

:::info
本体是企业知识的**语义骨架和类型系统**，用于统一跨部门、跨系统和跨数据源的业务语义。

:::

## 分类法、术语表、本体和知识图谱
| 概念 | 主要作用 |
| --- | --- |
| 分类法 Taxonomy | 定义知识分类和上下位关系 |
| 术语表 Glossary | 统一业务术语、缩写和口径 |
| 本体 Ontology | 定义概念、属性、关系、约束和规则 |
| 知识图谱 Knowledge Graph | 按照本体组织具体实体、关系和事实 |
| 语义模型 Semantic Model | 定义业务指标、维度、计算口径及数据映射 |
| LLM Wiki | 将原始资料持续编译成结构化、可链接的知识页面 |


本体与知识图谱概念关系：

> 本体定义企业如何认识和描述业务世界，知识图谱保存符合这些定义的具体业务事实。
>

## LLM Wiki
LLM Wiki是由大语言模型根据企业原始资料持续生成、关联、修订和审查的持久化知识表达层。

它将传统的“查询时临时总结”转变为“知识接入时持续编译”。

LLM Wiki可以形成以下类型的知识页面：

+ 概念说明；
+ 产品百科；

## RAG与智能检索
RAG负责在回答问题时从企业知识源中获取相关证据，并将证据提供给大语言模型。

企业级智能检索通常不是单一的向量检索，而是多种检索方式的组合：

```latex
全文检索
+ 向量检索
+ 元数据过滤
+ 权限过滤
+ 知识图谱检索
+ SQL查询
+ 业务API查询
+ 结果重排序
```

不同知识应采用不同的查询方式：

| 知识类型 | 适用方式 |
| --- | --- |
| 制度原文、精确条款 | 全文检索、关键词检索 |
| 语义相似问题 | 向量检索 |
| 实体关系和多跳问题 | 知识图谱、GraphRAG |
| 指标和明细数据 | SQL、语义查询 |
| 库存、价格、订单状态 | 实时业务API |
| 主题综述和背景知识 | LLM Wiki |
| 复杂综合问题 | Agentic Retrieval |


## AI Agent
AI Agent负责理解任务、制定计划、检索知识、调用工具和执行操作。

智能知识库与AI Agent的边界是：

+ 知识库负责提供知识、证据、语义和上下文；
+ Agent负责规划任务、选择工具和组织执行过程；
+ 业务系统负责保存和处理正式业务数据；
+ 工作流和规则引擎负责执行确定性业务规则；
+ 治理体系负责授权、审核、审计和追责。

:::info
知识库本身不应绕过业务系统直接修改交易数据。涉及例如：下单、退款、审批、付款和配置变更等操作时，应由Agent调用经过授权的业务API，并设置审批、审计、幂等和回滚机制。

:::

# 智能知识库的业务范围
## 知识对象范围
智能知识库可以管理或连接以下知识对象。

| 知识类型 | 内容 |
| :--- | :--- |
| 非结构化知识 | 制度和管理办法；产品手册；业务流程文档；合同和协议；项目文档；研究报告；会议纪要；FAQ和操作指南；邮件及沟通记录；培训材料；专家经验和最佳实践 |
| 半结构化知识 | PDF文件；Word和演示文稿；Excel表格；网页和Wiki页面；工单；表单；日志摘要；配置文件；API文档；代码和技术文档 |
| 结构化知识 | 客户、产品、供应商等主数据；业务指标；数据字典；组织架构；权限信息；订单、库存和项目状态；风险、质量和合规记录；数据库中的业务实体及关系 |
| 多模态知识 | 扫描件；图片和设计图；工程图纸；音频；视频；录音录像；设备影像；图表和仪表盘 |

## 典型服务对象
智能知识库应同时服务以下对象：

1. **企业员工**  
提供统一搜索、知识问答、业务辅助和决策支持。
2. **业务专家和知识管理员**  
提供知识编辑、审核、发布、冲突处理和质量管理能力。
3. **业务应用**  
通过API嵌入客服、办公、研发、销售和运营系统。
4. **AI Agent**  
提供任务上下文、业务语义、规则、证据和工具说明。
5. **客户与合作伙伴**  
在隔离和授权条件下提供产品、服务及合作知识。

# 智能知识库的业务边界
## 与业务源系统的边界
ERP、CRM、OA、MES、PLM和财务系统仍然是相应业务数据的权威来源，即System of Record。

智能知识库主要负责：

+ 接入和关联多系统知识；
+ 建立统一业务语义；
+ 构建检索索引和知识图谱；
+ 生成可阅读的知识页面；
+ 提供知识查询和上下文服务；
+ 根据权限返回证据和解释。

智能知识库原则上不替代业务系统，不直接成为订单、库存、资金和审批状态的最终记录系统。

## 与数据平台的边界
数据湖、数据仓库和湖仓平台负责原始数据存储、加工及分析；智能知识库负责将数据转化为可被人和AI理解的业务语义和知识服务。

```latex
数据平台解决“数据在哪里、如何计算”
智能知识库解决“数据表示什么、如何解释和使用”
```

对于大规模交易明细、日志和传感器数据，不应全部复制到知识库中。知识库可以保存其元数据、指标定义、摘要和语义映射，并在查询时调用数据平台。

## 与文档管理系统的边界
文档管理系统负责：

+ 文件存储；
+ 目录管理；
+ 版本管理；
+ 协作编辑；
+ 文件权限。

智能知识库在此基础上增加：

+ 内容解析；
+ 语义理解；
+ 跨文档关联；
+ 问答和推理；
+ 本体映射；
+ 知识图谱；
+ 知识质量及生命周期治理。

文档管理系统是重要知识源，但不等同于智能知识库。

## 与大语言模型的边界
大语言模型是语言理解和内容生成引擎，但不能天然作为企业事实来源。

必须坚持以下原则：

+ 企业权威来源高于模型参数知识；
+ 原始文件高于AI自动摘要；
+ 实时业务系统高于历史索引副本；
+ 已审核知识高于未审核生成内容；
+ 确定性规则高于模型自由推理；
+ 重要结论必须提供来源和证据；
+ 高风险决策必须经过人工或规则校验。

## 与AI Agent记忆的边界
需要区分企业知识、实时数据、Agent记忆和模型知识：

| 类型 | 主要内容 | 权威性 |
| --- | --- | --- |
| 企业知识 | 制度、产品、流程、规则和案例 | 经过治理后可作为企业依据 |
| 实时数据 | 订单、库存、价格和账户状态 | 以业务源系统为准 |
| Agent记忆 | 用户偏好、任务历史和交互状态 | 个性化信息，不一定权威 |
| 模型知识 | 模型预训练形成的通用知识 | 不得直接视为企业事实 |
| AI编译知识 | 摘要、Wiki页面、自动关系 | 需要保留来源和审核状态 |
| AI推论 | 趋势、原因和行动建议 | 属于分析判断，不等于事实 |


## 权限边界
用户通过智能知识库获取的内容不得超过其在源系统中的原有权限。

至少应支持：

+ 租户隔离；
+ 组织和部门隔离；
+ 项目及工作空间隔离；
+ 文档级权限；
+ 字段和行级权限；
+ 数据密级；
+ 查询时动态权限过滤；
+ 敏感信息识别和脱敏；
+ 用户身份与Agent身份区分；
+ 检索、生成和工具调用审计。

## 时间和有效性边界
每条重要知识应具备：

+ 来源；
+ 责任人；
+ 创建时间；
+ 生效时间；
+ 失效时间；
+ 当前版本；
+ 适用范围；
+ 权威等级；
+ 审核状态；
+ 最近同步时间；
+ 更新频率。

业务的实时信息，不应仅依赖向量索引中的历史副本，应在查询时访问业务API或数据库。

# 知识分级体系
建议按照来源和审核状态对知识进行分级。

| 等级 | 知识类型 | 示例 | 使用要求 |
| --- | --- | --- | --- |
| L0 | 原始权威来源 | 制度原文、合同原件、业务数据库 | 作为最终事实依据 |
| L1 | 已审核标准知识 | 正式Wiki、本体、术语、业务规则 | 可作为企业统一知识 |
| L2 | AI编译知识 | 自动摘要、自动生成Wiki、实体关系 | 应保留来源和审核状态 |
| L3 | AI推论 | 原因分析、趋势判断、行动建议 | 必须标记为推论或建议 |
| L4 | 临时上下文 | 会话内容、任务材料、Agent记忆 | 不应自动沉淀为公共知识 |

# 智能知识库体系框架
## 总体框架
企业级智能知识库建议采用八层体系框架：

其中权限、安全、溯源、审核、版本、评测和运营治理贯穿全部层级。

## 第一层：知识源与数据源
负责连接企业内部及外部知识来源。

### 内部知识源
+ 文档管理平台；
+ 企业网盘；
+ OA和门户；
+ Wiki；
+ ERP、CRM、MES、PLM等业务系统；
+ 数据仓库和数据湖；
+ 数据库和API；
+ 邮件、工单和会议系统；
+ 代码仓库；
+ 音视频平台；
+ 专家人工录入内容。

### 外部知识源
+ 法律法规；
+ 行业标准；
+ 政策文件；
+ 行业研究报告；
+ 产品资料；
+ 公开网站；
+ 经过授权的第三方数据库。

:::info
该层保留原始内容、原始权限和原始版本，不应因进入知识库而失去其来源属性。

:::

## 第二层：知识接入、解析与加工层
负责将不同类型的源数据转化为可处理的标准内容。

主要能力包括：

数据连接器；

文件解析；

OCR；

版面识别；

表格识别；

图片理解；

音视频转写；

代码解析；

内容清洗；

文档切分；

元数据提取；

文档分类；

敏感信息识别；

质量检查；

增量同步；

变化检测。

:::info
对于复杂文档，应保留标题层级、页码、表格结构、图片位置和章节关系，避免仅将内容处理成无结构文本片段。

:::

## 第三层：本体、术语与语义模型层
该层是企业智能知识库的语义控制中心。

主要内容包括：

+ 企业核心概念；
+ 业务实体类型；
+ 属性和枚举；
+ 实体关系；
+ 业务术语；
+ 同义词和缩写；
+ 分类体系；
+ 指标口径；
+ 业务规则；
+ 状态模型；
+ 数据字段映射；
+ 页面Schema；
+ 权限及密级分类。

本体建设可以采用“专家定义＋数据发现＋LLM辅助”的方式：

1. 领域专家定义核心业务概念；
2. 数据治理团队建立系统和字段映射；
3. LLM从文档中发现候选概念及关系；
4. 通过审核流程确认本体变更；
5. 将本体应用于抽取、检索、图谱和Agent。

:::info
LLM可以辅助构建本体，但企业核心语义、指标口径和业务规则不能完全由模型自动决定。

:::

## 第四层：LLM Wiki知识编译层
该层负责将原始资料和抽取结果持续编译为适合人和AI使用的知识页面。

主要能力包括：

+ 主题页面生成；
+ 实体页面生成；
+ 概念页面生成；
+ FAQ生成；
+ 操作指南生成；
+ 时间线生成；
+ 多文档综合；
+ 页面交叉链接；
+ 页面增量更新；
+ 版本差异分析；
+ 知识冲突检测；
+ 知识空白发现；
+ 来源和引用维护；
+ 页面审核及发布。

## 第五层：索引、知识图谱与存储层
该层负责持久化保存各种知识表达，并提供高效查询能力。

主要组成包括：

+ 原始文件存储；
+ 结构化知识存储；
+ 元数据目录；
+ 全文索引；
+ 向量索引；

不同存储应保持职责分离：

| 存储模块 | 功能描述 |

# 治理体系
## 知识治理
知识治理应覆盖知识的完整生命周期：

```latex
发现
→ 接入
→ 解析
→ 抽取
→ 编译
→ 审核
→ 发布
→ 使用
→ 反馈
→ 更新
→ 归档或失效
```

核心治理内容包括：

+ 知识分类；
+ 知识责任人；
+ 权威来源认定；
+ 审核和发布；
+ 版本管理；
+ 有效期管理；
+ 冲突处理；
+ 质量评分；
+ 使用反馈；
+ 归档及销毁。

企业级智能知识库不能只用“用户感觉不错”进行验收，应建立可量化评测体系。

+ 排序质量；
+ 权限过滤准确率；
+ 引用定位准确率；

+ 事实正确性；
+ 答案完整性；
+ 证据一致性；
+ 引用覆盖率；
+ 无依据内容比例；
+ 业务口径一致性；
+ 拒答合理性。

#### 知识质量评测
+ 知识完整度；
+ 新鲜度；
+ 重复率；
+ 冲突率；
+ 审核覆盖率；
+ 责任人覆盖率；
+ 过期知识占比。

#### 运营与价值评测
+ 用户活跃度；
+ 问题解决率；
+ 人工处理时间降低比例；
+ 知识复用率；
+ 业务流程效率；
+ 单次有效回答成本；
+ Agent任务完成率；
+ 风险事件减少比例。

```latex
知识源登记
→ 权限和密级确认
→ 内容同步
→ 文件及数据解析
→ 元数据提取
→ 内容质量检查
```

## LLM Wiki编译流程
```latex

→ 识别受影响页面
→ 提取新增和变更事实
→ 对比现有知识
→ 识别一致、补充、冲突或失效内容
→ 生成页面变更建议
→ 自动校验
→ 专家审核
→ 发布新版本

```

## 智能问答流程
```latex
用户身份认证
→ 问题意图识别
→ 权限范围计算
→ 本体和术语映射
→ 查询计划生成
→ 多源检索
→ 结果重排序
→ 证据一致性检查
→ 答案生成
→ 引用原文
→ 记录反馈和审计日志
```

```latex

→ 身份与权限确认
→ Agent制定计划

→ 必要时人工审批
→ 调用业务系统API
→ 记录执行结果和证据
→ 将有效经验按治理流程沉淀
```

# 设计原则
## 权威来源优先
所有重要知识必须能够回到原始来源。知识库生成的摘要和答案不能替代正式制度、合同原文和业务系统记录。

## 语义先行
企业级知识库不能仅依赖文档切分和向量检索，应逐步建设术语、分类、本体、指标口径和系统字段映射。

## 场景驱动
优先选择高频、高价值、知识基础较好且风险可控的场景，避免一开始追求覆盖企业全部知识。

## 分层治理
原始来源、审核知识、AI编译知识、AI推论和Agent记忆必须分层管理，不能混合为同等权威的内容。

## 权限不降级
知识接入、索引、检索、生成和Agent调用的每个环节都必须保留和执行权限控制。

## 实时数据不静态化
实时业务状态优先通过SQL或API获取，不应仅依赖历史向量索引。

## 证据与答案分离
系统应同时保存：

+ 检索到的证据；
+ 模型生成的答案；
+ 使用的模型和提示；
+ 调用的工具；
+ 最终执行结果。

## 人机协同
LLM适合辅助知识发现、抽取、整理和生成，但核心业务概念、制度、指标、规则和高风险结论仍需专家审核。

## 持续运营
知识库不是一次性交付项目，需要持续开展知识更新、用户反馈、质量评测、模型优化和业务运营。

# 成熟度模型
### L1：文档检索级
主要特征：

+ 文档统一接入；
+ 全文和向量检索；
+ 基础问答；
+ 简单引用。

局限：

+ 语义不统一；
+ 权限和治理能力有限；
+ 主要依赖文档片段。

### L2：知识问答级
主要特征：

+ 混合检索；
+ 权限过滤；
+ 多轮问答；
+ 答案引用；
+ 场景化知识库；
+ 基础评测。

### L3：知识治理级
主要特征：

+ 统一分类和术语；
+ 知识责任人；
+ 审核及发布流程；
+ 版本和有效期管理；
+ 知识质量评测；
+ 跨部门知识服务。

### L4：语义知识级
主要特征：

+ 企业本体；
+ 知识图谱；
+ 指标语义模型；
+ 实体消歧；
+ GraphRAG；
+ LLM Wiki；
+ 多源证据融合。

### L5：智能行动级
主要特征：

+ Agentic Retrieval；
+ 多Agent共享知识层；
+ 知识、实时数据和记忆协同；
+ Agent工具调用；
+ 执行规则与审批；
+ 任务结果反馈；
+ 知识持续编译和自动优化。

# 企业级验收标准
可以通过以下问题判断系统是否达到企业级智能知识库要求：

1. 每个重要答案能否定位到原始文件、页码、数据表或业务接口？
2. 用户权限变化后，检索权限能否及时同步？
3. 是否区分原始知识、审核知识、AI编译内容和AI推论？
4. 知识过期、冲突和失效后，系统能否发现并处理？
5. 是否能够统一不同系统中的业务概念和指标口径？
6. 是否支持文档、表格、图片、音视频、代码和结构化数据？
7. 是否支持全文、向量、图谱、SQL和API等混合查询？
8. 是否能够服务多个部门、业务应用和AI Agent？
9. 是否建立基于真实业务问题的检索和回答评测集？
10. 是否能够记录一次回答使用了哪些知识、模型和工具？
11. AI Agent的知识权限和操作权限是否独立管理？
12. 高风险回答和业务操作是否存在审核、审批及回滚机制？
13. 每类重要知识是否具有明确责任人和更新机制？
14. 平台是否能够量化业务价值、质量、性能和成本？

如果系统只能实现“上传文档并进行聊天”，它属于知识问答工具；只有同时具备语义、治理、权限、证据、评测及服务化能力，才接近企业级智能知识库。
