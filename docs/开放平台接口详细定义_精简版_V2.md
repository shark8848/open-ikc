## A. 知识库管理

### A-00 知识库类型规则

定义：对外知识库统一支持 `personal`、`team`、`enterprise` 三种类型。

| 类型 | 说明 | 关键校验 |
| --- | --- | --- |
| personal | 个人知识库 | 当前用户必须为库创建者 |
| team | 团队知识库 | 必须提供 teamId，且调用方属于团队 |
| enterprise | 企业知识库 | 建议提供 orgId，且调用方在企业授权范围内 |

统一约束：
1. 若知识库类型与调用主体权限不匹配，返回 `100403`。
2. 若 `team` 类型缺少 `teamId`，返回 `100001`。
3. 若 `enterprise` 类型无组织授权，返回 `100403`。

错误码体系：

| 错误码 | 层级 | 含义 | 适用范围 |
| --- | --- | --- | --- |
| 000000 | 成功 | 请求处理成功 | 所有知识库接口 |
| 100001 | 参数层 | 请求参数缺失、类型错误或校验失败 | 所有知识库接口 |
| 100401 | 认证层 | 未认证或认证失败 | 所有知识库接口 |
| 100403 | 鉴权层 | 无权限或越权访问 | 所有知识库接口 |
| 100404 | 资源层 | 目标知识库不存在 | 所有知识库接口 |
| 100409 | 冲突层 | 资源冲突、重复创建或状态冲突 | 所有知识库接口 |
| 200001 | 业务层 | 创建知识库失败 | 创建接口 |
| 200002 | 业务层 | 修改知识库失败 | 修改接口 |

异常继承与传递约定：

1. 业务层优先抛 `AppException` 或其子类，知识库领域可使用 `KnowledgeBaseException`。
2. 推荐通过错误码对象生成异常，例如 `error.as_exception(...)` 或统一工厂方法，避免在业务层手写返回体。
3. `ErrorCode.message` 作为默认错误描述，必要时可在抛出时覆盖 `message`，但错误码本身不变。
4. `AppException` 进入 API 层后统一转换为 `{errCode, errMsg, data}` 响应体。
5. 参数校验异常统一收敛到 `100001`，认证/鉴权/资源/冲突类异常分别收敛到 `100401/100403/100404/100409`。
6. `501001` 作为框架占位错误码，仅用于未实现接口，不建议业务正式态继续沿用。

TraceID 约定：

1. 所有接口请求会注入 23 位纯数字 `traceId`。
2. 优先读取请求头 `X-Request-Id`、`X-Trace-Id`、`traceId`、`trace_id`。
3. 响应头回写 `X-Request-Id` 和 `X-Trace-Id`，响应体顶层统一带 `traceId`。
4. 日志上下文由 `ikc-log-center` SDK 承接，便于在日志中心按链路检索。

错误码使用示例：

```python
from app.core.error_codes import CommonErrorCodes, exception_from_code

raise CommonErrorCodes.FORBIDDEN.as_exception(
  {"scope": "knowledge-base"},
  message="无权限访问当前知识库",
)

raise exception_from_code(
  CommonErrorCodes.INVALID_PARAMS,
  {"field": "kbId", "reason": "不能为空"},
)
```

错误码查询示例：

```python
from app.core.error_codes import BaseErrorCodes, error_code_catalog

error = BaseErrorCodes.get_by_code("100403")
catalog = error_code_catalog()
```

在线错误码目录：

- 接口：`GET /api/error-codes`
- 返回：`{status, data, traceId}`，其中 `data` 为错误码对象数组，字段包含 `code`、`message`、`level`、`description`

### A-01 创建知识库

- 方法：POST
- 路径：/openapi/v1/knowledge-bases/create
- 定义：创建新的知识库并返回库标识。
- 描述：用于初始化一个可接收文档、可构建索引、可执行检索的知识库。知识库类型支持个人、团队、企业。

请求体说明：

| 字段 | 类型 | 必填 | 默认值 | 详细说明 |
| --- | --- | --- | --- | --- |
| kbName | string | 是 | 无 | 知识库名称，面向用户展示，需在同一组织/租户内尽量唯一。 |
| kbType | string | 否 | personal | 知识库类型：personal 个人库、team 团队库、enterprise 企业库。若选择 team 或 enterprise，后续权限与可见范围将按类型收敛。 |
| teamId | string | 否 | "" | 团队知识库标识；当 kbType=team 时必填，用于校验团队归属和调用者是否属于该团队。 |
| orgId | string | 否 | "" | 企业知识库组织标识；当 kbType=enterprise 时建议填写，用于租户隔离、组织授权和检索范围控制。 |
| kbDesc | string | 否 | "" | 知识库描述，用于说明业务场景、使用边界和维护责任。 |
| bizDomain | string | 否 | general | 业务域标签，例如 hr、finance、customer_service，用于前端分类和后续治理统计。 |
| visibility | string | 否 | private | 可见范围：private 表示仅创建者或授权范围内可见，org 表示组织内共享。 |
| metadataSchema | array<object> | 否 | [] | 元数据字段定义列表，用于约束知识库录入字段、检索过滤条件和权限标签。 |

条件校验规则：

1. 当 `kbType=team` 时，`teamId` 必填，且调用方必须属于对应团队。
2. 当 `kbType=enterprise` 时，`orgId` 建议填写；若平台侧未能通过调用主体识别组织授权，应返回 `100403`。
3. `visibility=org` 时，知识库结果默认按组织内授权范围可见，仍需结合调用主体权限过滤。

`metadataSchema[]` 对象说明：

| 字段 | 类型 | 必填 | 默认值 | 详细说明 |
| --- | --- | --- | --- | --- |
| name | string | 是 | 无 | 元数据字段名，建议使用英文或拼音标识，需在同一知识库内唯一。 |
| type | string | 是 | 无 | 字段类型：string、number、integer、boolean、date、datetime、enum、object。 |
| required | boolean | 否 | false | 是否必填。为 true 时，后续文档录入或补充时必须提供。 |
| description | string | 否 | "" | 字段业务含义说明，建议写明用途、口径和使用边界。 |
| defaultValue | any | 否 | null | 默认值；当调用方未传该字段时可采用此值。 |
| enum | array<string> | 否 | [] | 枚举值集合；当 type=enum 时建议填写，便于前端下拉展示和后端校验。 |
| pattern | string | 否 | "" | 正则约束，适用于字符串类字段的格式校验。 |
| minLength | integer | 否 | null | 字符串最小长度。 |
| maxLength | integer | 否 | null | 字符串最大长度。 |
| example | any | 否 | null | 字段示例值，用于文档展示和联调参考。 |

`visibility` 取值说明：

| 取值 | 说明 |
| --- | --- |
| private | 私有可见，仅创建者或显式授权范围内可访问。 |
| org | 组织可见，组织内授权用户可访问。 |

条件校验规则同 A-01。

入参：

| --- | --- | --- | --- | --- |
| kbName | string | 是 | 无 | 知识库名称 |

### A-04 查询知识库列表

- 方法：POST
- 路径：/openapi/v1/knowledge-bases/query
- 定义：按类型、团队/组织范围与关键字分页查询调用方可访问的知识库。
- 描述：列表结果按调用方数据权限收敛：个人库仅返回本人创建，团队库需携带 `teamId`，企业库按 `orgId` 或调用主体租户收敛。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| kbType | string | 否 | 全部 | 按知识库类型过滤：personal/team/enterprise |
| teamId | string | 否 | "" | 查看团队库时必填，用于成员范围收敛 |
| orgId | string | 否 | "" | 查看企业库时建议填写，为空时使用调用主体租户 |
| ownerId | string | 否 | "" | 个人库创建者过滤（个人库始终按调用方身份收敛） |
| keyword | string | 否 | "" | 按名称或描述关键字过滤 |
| page | integer | 否 | 1 | 页码，从 1 开始 |
| pageSize | integer | 否 | 20 | 每页条数，最大 100 |

出参：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| traceId | string | 请求链路追踪 ID |
| errCode | string | 错误码 |
| errMsg | string | 错误信息 |
| data.total | integer | 命中总数 |
| data.page | integer | 当前页码 |
| data.pageSize | integer | 每页条数 |
| data.items | array<object> | 知识库列表（字段同 A-03 data） |

## B. 知识管理

### B-00 接入与解析编排模式

- `split`（推荐）：先 `ingest`，后 `parse`。
- `quick`（快捷）：一次调用 `ingest-and-parse`。

说明：
1. `split` 适用于批量、长任务、可重试场景。
2. `quick` 适用于单文件、低延迟接入场景。
3. `quick` 内部仍按两阶段执行，返回可追踪任务 ID。

### B-01 接入知识源

- 方法：POST
- 路径：/openapi/v1/knowledge-documents/ingest
- 定义：接入知识源并登记到指定知识库。
- 描述：统一支持 URL、文件、目录、压缩包四种来源形态。

入参：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |

| kbId | string | 是 | 无 | 知识库 ID |
| teamId | string | 否 | 无 | 当目标知识库类型为 team 时建议传入 |
| orgId | string | 否 | 无 | 当目标知识库类型为 enterprise 时建议传入 |
| source | object | 是 | 无 | 来源对象 |
| source.type | string | 是 | file | 来源类型：url/file/directory/archive |
| source.url | string | 否 | "" | 当 source.type=url 时必填 |
| source.objectKey | string | 否 | "" | 文件/目录/压缩包对象标识 |
| source.fileToken | string | 否 | "" | 文件上传凭证或临时对象标识 |
| source.archive | object | 否 | {} | 压缩包配置 |
| source.archive.format | string | 否 | zip | zip/7z/tar/tar.gz |
| source.archive.passwordRef | string | 否 | "" | 加密压缩包密码引用 |
| source.archive.includePattern | array<string> | 否 | [] | 解压后纳入处理的文件匹配 |
| source.archive.excludePattern | array<string> | 否 | [] | 解压后排除文件匹配 |
| source.directory | object | 否 | {} | 目录配置 |
| source.directory.recursive | boolean | 否 | true | 是否递归目录 |
| source.metadata | object | 否 | {} | 来源元信息 |
| docTitle | string | 否 | 自动推断 | 文档标题 |
| tags | array<string> | 否 | [] | 标签列表 |
| metadata | object | 否 | {} | 自定义元数据 |
| orchestrationMode | string | 否 | split | split/quick |

出参：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| traceId | string | 请求链路追踪 ID |
| errCode | string | 错误码 |
| errMsg | string | 错误信息 |
